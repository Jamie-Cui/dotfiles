This is the Emacs package inside the parent dotfiles repository.  GNU Stow
deploys its managed files into the conventional =~/.emacs.d= directory while
runtime state remains outside Git.  It uses two-level
deferred loading, Evil mode, and gptel LLM integration. Targets Emacs 30.1+.

** What this config does?
1. Use melpa only.
2. Use emacs version 30.1.
3. Use Maple Mono NF CN (NO Ligature!): [[https://github.com/subframe7536/maple-font][repo]], [[https://github.com/subframe7536/maple-font/releases/download/v7.8/MapleMonoNL-NF-CN-unhinted.zip][download]].
4. Use Plantuml for uml drawing: [[https://github.com/plantuml/plantuml/releases/download/v1.2024.7/plantuml-1.2024.7.jar][download]].
5. Use emacs build-in tree-sitter.

* Architecture

The configuration loads in three layers:

1. *Bootstrap*. ~early-init.el~ runs first (GC tuning and early UI chrome).
   ~init.el~ locates the managed source, applies user settings, then loads the
   core layer and feature-module manifest.
2. *Core* (~lisp/core/~). Foundational mechanics, loaded with ~require~ in a fixed
   order: ~core-vars~ (user variables, ~+emacs~ group), ~core-paths~ (load paths and
   directory helpers), ~core-startup~ (version gate, startup restore, proxy,
   workarounds, server), ~core-package~ (package.el + use-package), ~core-loader~
   (the module loader), ~core-util~ (cross-cutting commands).
3. *Modules* (~lisp/modules/~). One file per capability domain, each providing a
   feature named ~init-<module>~. Language packages live in ~lisp/modules/lang/~,
   loaded by path-like names such as ~lang/cmake~.

Modules load in manifest order; ~keys~ loads last so every command it binds is
already defined. Remove or comment a manifest entry in ~init.el~ to disable that
module. The loader performs no dependency inference, so manifest membership and
order are the contract.

** Module boundaries

| Module                 | Responsibility                                            |
|------------------------+-----------------------------------------------------------|
| ~os~                     | OS-specific tweaks (Linux/macOS/Windows/WSL), shell env   |
| ~ui~                     | frames, fonts, cnfonts, modeline, dashboard, themes, TTY  |
| ~editor~                 | editing defaults, smartparens, yasnippet, Harper, text commands |
| ~completion~             | vertico/corfu/consult/orderless/marginalia, embark        |
| ~files~                  | dired, tramp, eshell, eat, backups, auto-save, proced     |
| ~project~                | projectile, envrc                                         |
| ~vc~                     | magit, diff-hl, git-foreign-magit, git-overleaf            |
| ~prog~                   | eglot, flycheck, citre, compilation, treesit              |
| ~lang/*~                 | language-specific config: C/C++, Rust, Python, CMake, ... |
| ~lang/org~               | Org core, babel, export, plantuml                         |
| ~notes~                  | org-project, background CalDAV, journal, roam, denote      |
| ~bibliography~           | citar, ebib, bibtex                                       |
| ~lang/latex~             | AUCTeX, RefTeX, Xenops, engrave-faces, SyncTeX (GUI)        |
| ~pdf~                    | PDF Tools, continuous scrolling, prefetch, viewer keys (GUI) |
| ~reading~                | elfeed                                                    |
| ~llm~                    | gptel, agent-shell, magent, Action status, magent-magit   |
| ~llm-config~             | GPTel backends, model discovery/cache, defaults           |
| ~input~                  | PDF/text zoom, pinch and mouse-wheel handlers             |
| ~keys~                   | which-key, general.el, the SPC leader map (loaded last)   |

Local and forked packages live in ~site-lisp/~ and keep their own ~init-config-*~
helper files in ~lisp/~.

~prog~ owns shared programming infrastructure; language-specific server and
checker policies live in ~lang/*~.  Language association hooks run after the
generic treesit-auto registration.  ~editor~ registers Harper lazily with Eglot.
~pdf~ can be enabled without LaTeX; ~lang/latex~ adds SyncTeX once both TeX and
PDF Tools are loaded.  The existing ~+prog/rust-*~ and ~+latex/roll-*~ names are
retained for compatibility.  Overleaf integration loads with ~vc~ in both
graphical and terminal sessions.

~org-project-caldav~ extends ~org-project~ without depending on the standalone
~org-caldav~ package.  Project files, the CalDAV inbox, and synchronization
state live below =~/.emacs.d/org-project-caldav/=, separately from the knowledge
base in =~/opt/org-root/=.  A =project-files/default.org= project is created
during setup so manual captures always have a CalDAV-backed fallback.  Every
Org file below the task root is checked, but only active leaf tasks are
represented as CalDAV ~VTODO~ items.

Org journal files live below =~/opt/org-root/journal/= and are deliberately
excluded from ~org-agenda-files~, so TODO-like journal text is local history
rather than a CalDAV task.  Project capture and task-state events may still be
appended there as immutable records.
Synchronization runs every five minutes and shortly after an Org save.  Network
work runs in a background ~vdirsyncer~ process; credentials come from Emacs
~auth-source~ and are passed only in that process's environment.  Reconciliation
runs against a staging vdir, and a coverage check prevents committing a partial
active-task projection.
The only non-Emacs dependency is ~vdirsyncer~.  Use
~M-x org-project-caldav-sync~ for an immediate run and
~M-x org-project-caldav-status~ to inspect its state.
If no project Org files remain, manual synchronization asks in the minibuffer
before recreating =project-files/default.org=.  If missing source files also
remove previously synchronized task IDs, it asks before accepting those
removals (including deletion of matching CalDAV tasks).  Approval applies only
to the reviewed paths and IDs in that cycle.  Background synchronization waits
for manual confirmation without a warning popup.

* Protocol blocks

Use =protocol= followed by snippet expansion to insert a LaTeX protocol:

#+begin_example
#+name: example-protocol
#+begin_protocol
\small
\textbf{Example protocol}
\begin{enumerate}
\setlength{\itemsep}{3pt}
\setlength{\parsep}{0pt}
\item The client sends a request.
\item The server returns a response.
\end{enumerate}
#+end_protocol
#+end_example

The body is raw LaTeX, highlighted like a =latex= source block using the current
theme when =org-src-fontify-natively= is enabled.
The configuration supplies the =protocol= environment,
shared packages and white preview background.  Press =C-c C-c= inside the block
or run =M-x +org/protocol-preview= to generate =img/example-protocol.svg= and
insert or update its result below the source:

#+begin_example
#+RESULTS: example-protocol
[[file:img/example-protocol.svg]]
#+end_example

Save the buffer to keep this link; Org can display it again when reopening the
file.  After editing the protocol, render it again to update the saved image.
Repeated rendering replaces the existing result.  Unnamed blocks use a content
hash for the image filename and an anonymous =#+RESULTS:= line.

LaTeX/PDF export embeds the protocol source directly.  Other backends render
an SVG and export its link.  Both omit the saved result to avoid duplicate
output; Org export preserves the editable block and result.  SVG
rendering uses the same XeLaTeX and =pdftocairo= setup as LaTeX Babel blocks.
For migration, remove the old Babel headers, outer =\begin{protocol}= /
=\end{protocol}=, then replace the source block delimiters with
=#+begin_protocol= / =#+end_protocol=.  The existing adjacent =RESULTS= file
link can remain.

** Install

#+begin_src bash
cd ~/opt/dotfiles
make dry-run
make bootstrap
#+end_src

The parent repository links only managed source files into =~/.emacs.d= with
Stow's no-folding mode.  ELPA packages, caches, history, databases, backups,
and other runtime files remain ordinary files in =~/.emacs.d= and are not part
of Git.

User settings such as identity, proxy, paths, package mirrors, theme, and module
selection live in the managed ~init.el~.  Settings needed before the first frame
live in ~early-init.el~.  Customize writes to the untracked =~/.emacs.d/custom.el=.

Useful checks: ~make smoke~ (offline startup test of both chains) and
~make compile~ (byte-compile core + modules to a temp dir).


** Prerequisite
- gcc toolchain (gcc, g++, cmake, makefile, autotools, ...): compile environment
- libgccjit: for emacs's native compilation feature
- libsqlite3: for org-roam database
- libtree-sitter (tested with version 0.25.8, [[https://github.com/tree-sitter/tree-sitter][repo]]): for tree-sitter,
- (optional) texlive: for latex
- (optional) direnv: for separating project envs (~sudo dnf install direnv~)

#+begin_src bash
# macos, if you have not done so, in ~/.zshrc
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/opt/homebrew/lib/
# why tree-sitter@0.25? see: https://github.com/jdtsmith/emacs-mac/issues/121
brew install autoconf texinfo libgccjit gcc gnutls tree-sitter@0.25 pkg-config coreutils
#+end_src

** Download and Compile Emacs

#+begin_src bash
# download
wget -c https://github.com/emacs-mirror/emacs/archive/refs/tags/emacs-30.1.tar.gz
# or the following dev branch with tty-child-frame feature
wget -c https://github.com/emacs-mirror/emacs/archive/refs/heads/scratch/tty-child-frames.zip

# unzip and enter emacs folder
./autogen.sh
# (opt) configure terminal emacs
./configure --with-native-compilation --with-tree-sitter --with-gnutls --without-x-toolkit --without-xpm --without-gif --without-tiff --with-sqlite3 --without-pop --without-mailutils
# (opt) configure gui emacs with tiling window manager (WARNING: fcitx will not be avaliable inside emacs)
./configure --with-native-compilation --with-tree-sitter --with-sqlite3 --with-rsvg --without-pop --without-mailutils --without-x-toolkit
# (opt) configure gui emacs with pgtk
./configure --with-native-compilation --with-tree-sitter --with-sqlite3 --with-rsvg --without-pop --without-mailutils --with-pgtk
# (opt) configure gui emacs with default x toolkit (for MacOS)
./configure --with-native-compilation --with-tree-sitter --with-sqlite3 --with-rsvg --without-pop --without-mailutils --with-x-toolkit
# compile
make -j
# install
sudo make install
#+end_src

MacOS: libgccjit failed to compile and run? see: https://github.com/d12frosted/homebrew-emacs-plus/issues/680#issuecomment-2103717530

Have tree-sitter problem? see: [[https://www.reddit.com/r/emacs/comments/1e57kzy/a_solution_for_getting_emacs_to_compile_with/?utm_source=share&utm_medium=web3x&utm_name=web3xcss&utm_term=1&utm_content=share_button][link]]. Or download tree-sitter pre-built binaries [[https://github.com/emacs-tree-sitter/tree-sitter-langs][here]].
